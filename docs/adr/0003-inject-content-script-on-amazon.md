# 向 amazon.com 注入内容脚本
目标工作流的核心入口是**亚马逊搜索结果页**：用户在一页几十个结果里看中某一件。搜索页 URL 不含 ASIN，侧边栏无法只凭 URL 知道用户指哪一个，因此需要向 amazon.com 注入内容脚本，读取卡片上的可见信息并提供选中态。已确认接受由此带来的站点条款与改版维护风险。
## Considered Options
- **只做 Chrome 侧边栏，不注入**：零站点风险，但搜索页里无法确定分析对象，需要用户手动打开商品详情页——与用户的实际工作流冲突。
- **只注入极小入口脚本**（读 `location.href` 后投递给侧边栏，不解析卡片 DOM）：站点风险最低，但同样拿不到「搜索页里指哪一件」。
## Consequences
- 扩展需要 `amazon.*` 主机权限与新增 `amazon` target，`wxt.config.ts` 的 `host_permissions` 扩大。
- 搜索结果页解析进入维护范围：Amazon 改版时必须跟随；解析失败一律静默降级，不得弹错误。
- 页面性能预算成为硬约束：注入脚本必须在 Amazon 主页面渲染之外异步执行，不阻塞首屏。
- 采集范围限定为用户可见的页面信息与公开字段，不读取买家个人数据。
