# 面板外壳改为对话优先
面板的主面从「七个分区平铺」改为一条对话串：数据作为回答里的证据出现，主动翻数据退到默认收起的数据抽屉。词位表、评论痛点、视图规格这些已经建好的数据层与渲染组件保留，被吸收进对话与抽屉两处，而不是重写。

四种外壳（深色控制台、浅色分析台账、对话优先、焦点检视台）在 `docs/prototypes/panel-shell-prototype.html` 里同屏对比过，同一份假数据渲染。选定对话优先的理由：本产品的用法是「看着亚马逊页面问问题」，而不是坐下来批量看表；#11 已经实现了证据包问答，#13 的视图规格正是内嵌视图的机制，对话优先让已有的两层直接成为主面，改动集中在外壳。
## Considered Options
- **深色控制台**：沿用现有视觉与卡片分区，改动最小。放弃原因：它和现在没有本质区别，没有解决「看数要靠自己翻字段」的问题。
- **浅色分析台账**：密集表格加粘性表头，适合一次看很多行。放弃原因：为「批量对比」优化，而本项目已经判定批量自动选品不是主线（ADR-0001）。
- **焦点检视台**：一个超大读数当焦点，抽屉式深入。放弃原因：把一个对象的单点指标当焦点，与「就当前对象提问」相比信息上限更低。
## Consequences
- 面板第一屏不再默认展示词位表，用户要主动打开数据抽屉才能逐行翻数据；不习惯问答的用户成本上升。
- 对话是过程，不跨会话保留；值得留下的结论写进研究记录（归属人、小组、状态已由 #16 的服务端身份决定）。
- 侧边栏与页面内浮层继续并存（ADR-0004），但视觉先抽成一份共享样式来源，两边各自引入，不再各写一份。
- 数据抽屉与对话串共用同一份证据包；回答里的内嵌视图点击后展开抽屉并定位到对应分区，两处不出现不同数据。
- `apps/web` 工作台不在本次范围内，继续按 ADR-0001 冻结。

## 追加决定（同日第二轮）

- **整表不进气泡**：气泡只放文字与一行摘要，加一个指向数据抽屉的入口；词位表这类宽表在面板宽度里读不动，放进气泡会挤掉对话本身。
- **引用用句中标号**：模型仍只输出事实与它引用的来源 ID，渲染层把 ID 映射成句末上标数字，底部按序号列出来源清单。校验继续发生在 ID 上，标号是渲染产物——模型不负责编号，避免长回答里编号漂移。
- **追问带上文**：最近 2–3 轮的问答作为上下文发送，超限时截断。这会改动 `AnalysisAskRequest` 契约（当前是精确键校验），并且服务端要对每一轮历史重跑越界校验，否则上一轮的回答可以夹带越界内容绕过输入侧检查。
- **协议与 Worker 的输出结构不变**：`facts` / `inferences` / `citations` / `views` 保持原样，只改渲染层；带上文带来的契约变化仅限于新增历史字段与对应的逐轮校验。
- **切对象即清空对话**：分析对象或身份变化时对话串清空，不显示上一个对象的问答（与 #16 对研究记录的要求一致）。

## 视觉方向（同日第三轮）

采用原型 C 的暖白纸感配色：底 `#fbf8f3`、纸面 `#fff`、分隔线 `#e7ded1`、正文 `#2b2622`、次要文字 `#7d7368`、气泡 `#f2ece3`，强调色为陶土色 `#b0632c`，衬线体做标题。这**替换**现在侧边栏与浮层的深色橙青外壳（`panel.css` 与 `overlay.ts` 的 `STYLE`），不是并存。

- **强调色分两个 token**：`--accent #b0632c` 只用于色块、圆点、按钮底色；`--accent-ink #8f4a1e` 用于小字（分区标题、引用标号、来源清单序号），因为 `#b0632c` 压在暖白底上对比度只有 4.25:1，低于正文标准。
- **配色差异只应出现在 token 层**：侧边栏与浮层引用同一组 token，浮层因为在 shadow DOM 里而需要内联，所以 token 以 CSS 文本模块的形式共享。
- **深色外壳不再维护**：不保留深色主题开关；若将来要深色，按同一组语义 token 换值实现，而不是复活旧样式。
