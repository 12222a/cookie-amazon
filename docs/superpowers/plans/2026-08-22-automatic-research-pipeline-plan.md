# 自动选品研究流水线实施方案

- 日期：2026-08-22
- 状态：已批准，进入实施
- 产品：跨境选品助手
- 目标：将现有类目发现、ASIN 反查、关键词挖掘、ABA、竞品市场、评论分析和决策能力统一为低耦合、可恢复、受预算约束的自动研究任务。

## 1. 产品边界

用户只选择站点和类目，系统自动执行：

```text
类目发现 Top 3 ASIN
→ 自动分层反查
→ 聚合、去重并选择种子词
→ 限量调用关键词挖掘
→ 对高价值关键词调用 ABA
→ 查询代表性关键词的竞品和市场结构
→ 深化差评分析
→ 综合全部证据输出“继续验证 / 观察 / 放弃”
```

输出表示“值得进一步验证的产品机会”，不代表可直接采购、可立即上架或保证盈利。采购成本、物流、广告、税费、退货和合规数据缺失时，不得输出“高利润”等结论。

## 2. 设计原则

1. **纯业务核心**：研究规则不依赖 React、浏览器 API、扩展或 SellerSprite 原始响应。
2. **端口与适配器**：核心只依赖小型业务端口；Web 层把现有 Web SDK 适配为端口。
3. **阶段隔离**：每个阶段独立输入、输出、状态、预算和错误，不共享可变隐式状态。
4. **部分成功优先**：单个 ASIN 或关键词失败时保留已有证据并继续；鉴权、权限和协议级错误才中止远端阶段。
5. **请求受控**：默认串行远端调用，任务内缓存，有限重试，明确预算。
6. **证据可追溯**：评分、痛点和结论都保留来源、覆盖度和缺失信息。
7. **安全最小化**：只处理协议白名单后的数据，不保存或输出登录凭证和原始敏感响应。
8. **能力降级**：市场不支持、接口不可用或字段缺失时跳过对应阶段并降低可信度，不伪造数据。

## 4. 领域模型

### 4.1 研究任务

`ResearchJob` 包含：

- 输入：市场、类目、策略版本；
- 任务状态和当前阶段；
- 各阶段 `idle/running/complete/partial/skipped/failed/cancelled` 状态；
- 请求预算使用量；
- 候选商品、关键词、ABA、市场和评论证据；
- 风险、数据覆盖度和缺失信息；
- 最终四维评分和结论。

### 4.2 四维决策

- `Demand`：需求质量；
- `Entry`：市场进入条件；
- `Differentiation`：差异化空间；
- `Confidence`：证据可信度。

缺数据时默认偏向“观察”，不能因为缺数据直接判定“放弃”。

## 5. 业务端口

核心定义以下端口：

- `ProductDiscoveryPort`
- `KeywordReversePort`
- `KeywordMiningPort`
- `AbaResearchPort`
- `CompetitorResearchPort`
- `MarketResearchPort`
- `ReviewResearchPort`

所有端口接收领域输入并返回清洗后的领域证据，不返回第三方原始响应。

## 6. 默认研究策略

### 6.1 候选分层

- Tier A：Top 1，完整研究；
- Tier B：Top 2–3，标准研究；
- Tier C：Top 4–10，仅作为市场对照；
- 有效候选不足 3 个时使用已有候选继续；
- 重复 ASIN 去重，父子变体保留关联标记。

### 6.2 关键词反查

- 最多反查 Top 3 ASIN；
- 默认串行；
- 单个失败不终止；
- 保留关键词来源 ASIN、候选层级、排名、相关性、搜索量、购买率和供需比。

### 6.3 种子词选择

关键词进行保守标准化：小写、Unicode 标准化、空格和标点清理，同时保留原词。品牌词标记并降权，不直接删除。

默认选择最多 3 个具有多样性的种子词：

1. 核心大词；
2. 高购买意图长尾词；
3. 属性、用途或场景词。

评分考虑 ASIN 覆盖数、相关性、搜索量、购买率、供需比、排名和品牌可能性。字段缺失时按可用字段重新归一化。

### 6.4 关键词挖掘

- 最多 3 个种子词；
- 每词只请求第一页；
- 每页最多 50 条；
- 聚合去重后保留 Top 50；
- 扩词失败时回退到反查词池。

### 6.5 ABA

- 每任务加载一次周期；
- 默认使用最新周度周期；
- 周度不可用时回退最新月度；
- 最多验证 5 个高价值关键词；
- 保留排名、搜索量、购买率、排名变化、Top 3 点击份额和转化份额；
- ABA 不可用时跳过并降低可信度。

### 6.6 竞品与市场结构

从关键词簇中选择最多 3 个代表词：核心词、高意图长尾词、差异化场景词。

聚合指标包括：

- 商品数和月销量；
- Top 10 销量集中度；
- 品牌和卖家集中度；
- FBA、AMZ、FBM 结构；
- 价格带和评论壁垒；
- Listing Age、新品占比和新品进入表现；
- 关键词供需结构和数据覆盖度。

### 6.7 评论分析

- Top 3 商品默认各读取最新一页；
- 低星样本不足时允许受预算约束地补充 1–3 星评论；
- 痛点分类覆盖质量、尺寸适配、材质、性能、安装使用、包装运输、描述不符、外观颜色、价值感、配件、变体和售后；
- 每个痛点输出频次、低星占比、涉及 ASIN、涉及变体、平均星级、代表片段、覆盖度和改进方向；
- 没有评论证据时不生成虚假缺陷。

## 7. 默认请求预算

| 能力 | 默认最大调用 |
|---|---:|
| 选产品 | 1 |
| ASIN 反查 | 3 |
| 关键词挖掘 | 3 |
| ABA | 5 |
| 代表词竞品扫描 | 3 |
| 市场结构查询 | 3 |
| 评论查询 | 6 |

规则：

- 远端请求默认并发 1；
- 任务内对相同市场、ASIN、关键词和周期缓存；
- 网络错误和 429 只进行有限重试；
- 400、401、403 和合同错误不盲目重试；
- 支持 `AbortSignal` 取消，旧任务不能覆盖新任务。

## 8. 常见情况与降级

| 情况 | 行为 |
|---|---|
| 候选不足 3 个 | 使用现有候选继续 |
| 无有效候选 | 输出证据不足或放弃，并说明筛选条件 |
| 单个 ASIN 反查失败 | 阶段标记 partial，继续其他 ASIN |
| 没有反查词 | 回退标题词或输出观察 |
| 扩词失败 | 使用反查词池继续 |
| ABA 周度不可用 | 回退最新月度 |
| ABA 完全不可用 | 跳过并降低可信度 |
| 品牌词占比高 | 标记品牌流量风险 |
| 商品无评论 | 标记新品或评论证据不足 |
| 无低星评论 | 不生成痛点 |
| 429 | 有限退避后暂停该能力 |
| 未登录或无权限 | 停止远端阶段并保留已有结果 |
| 非 JSON 或合同漂移 | 阶段失败，原始响应不透传 |
| 用户切换类目 | 取消旧任务并启动新任务 |
| 未验证站点 | 按能力矩阵跳过阶段 |
| 利润字段缺失 | 不输出盈利结论 |

## 9. 最终结论

### 继续验证

需求达到门槛、进入条件未出现明显硬阻断、存在可验证差异化线索且证据覆盖度足够。

### 观察

需求存在但竞争集中、不同证据冲突、评论不足、关键接口部分失败、季节性不明确或覆盖度不足。

### 放弃

多个代表词需求均弱，或 ABA 与关键词共同显示购买意图弱，且市场集中、新品进入困难、评论/品牌壁垒高并缺少稳定差异化空间。

所有结论必须列出：

- 支持结论的证据；
- 风险和冲突证据；
- 缺失信息；
- 数据覆盖度；
- “不能判断真实利润”的边界声明。

## 10. 实施顺序

### 第一批：任务骨架

- 创建 `research-core`；
- 定义模型、端口、策略、预算、取消和阶段状态；
- 迁移并复用 P0 候选发现；
- Web 展示任务进度。

### 第二批：关键词自动化

- Top 3 反查；
- 聚合去重和品牌词标记；
- 种子词选择；
- 限量扩词和关键词簇。

### 第三批：ABA 和市场结构

- 周/月周期降级；
- 高价值词限量验证；
- 代表词竞品与市场查询；
- 集中度和新品进入分析。

### 第四批：差评与最终决策

- 评论自适应采样；
- 痛点主题、频次和变体关联；
- 四维评分；
- 最终“继续验证 / 观察 / 放弃”。

### 第五批：真实环境加固

- 登录、权限、429、非 JSON、网络失败、合同漂移；
- 任务取消、陈旧响应隔离、部分失败和恢复；
- 不同类目、低数据量和非美国站降级验证。

## 11. 测试与验收

### 核心单元测试

- 候选不足、重复和非法 ASIN；
- 关键词标准化、来源聚合、种子词多样性；
- 缺失字段重新归一化；
- 品牌词降权；
- ABA 周/月回退；
- 代表词选择；
- 评论痛点分类和无证据不生成；
- 四维评分、覆盖度和结论边界；
- 请求预算、部分失败和取消。

### 适配器测试

- 每个端口构造正确请求；
- 第三方数据映射为最小领域证据；
- 敏感字段无法进入领域模型；
- 登录、权限、429、网络和合同错误分类正确。

### 集成验收

- 用户只选择站点和类目即可启动；
- Top 3 自动进入后续研究；
- 页面实时显示阶段、进度、部分失败和预算；
- 最终结论可追溯到具体证据；
- 缺少成本数据时不声称利润；
- 旧任务结果不能覆盖新任务；
- 全工作区测试、类型检查和生产构建通过。
